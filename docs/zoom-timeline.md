# 可縮放時間軸（zoom.html）：運作邏輯、呈現方式與設計依據

> 這份文件寫給要幫忙提出改進方法的人或 AI。它說明這一頁**目前怎麼運作、為什麼這樣設計、已經試過並被否決的做法**，最後列出已知的限制和待解的問題。
> 提建議時，請先看第 7 節「使用者已經明確要求的事」，不要提出會把那些改回去的方案。

---

## 1. 這是什麼

- **主題**：臺灣「智能障礙」相關的歷史，1962–2025 年。
- **形式**：單一 HTML 檔 `zoom.html`。
  - 不連到其他頁面，也不讀外部圖檔，網站圖示直接寫在檔案裡。
  - 只有字型會向 Google Fonts 載入，載不到時改用裝置內建字型。
  - 所有資料都寫在檔案裡，不需要伺服器或資料庫。
- **內容**：一條可縮放的橫向時間軸，畫出 50 件事件。點一件事，時間軸**下方**會出現它的介紹卡，介紹卡最上面是「易讀版」。
- **讀者**：一般大眾、學生、特教相關人員，也包括智能障礙者本人（所以有易讀版與大字）。目標是符合 WCAG 2.2 AA，也就是臺灣「網站無障礙規範(115.11)」的標準。
- **它屬於哪個專案**：「智能障礙事件樹」數位策展網站。正式網站是 `index.html`，這一頁是從「時間軸版本比較」原型（`timelines.html` 的版本 7）獨立出來的。

## 2. 資料

### 2.1 50 件事件從哪裡來

| 類型 | 件數 | 來源 | 挑選方式 |
|---|---|---|---|
| 重大事件（三個分支：智力測驗、適應行為量表、法規與鑑定） | 18 | 研究團隊整理的「智能障礙重大事件表」（`source/src/00-data.js` 的 `TREE.events`） | 全部收入 |
| 剪報 | 15 | 738 篇報紙剪報的編碼資料，1962–2022 年（`source/data.json`） | 由 `source/pick_events.py` 依規則挑選，見下方 |
| 研究 | 9 | 426 篇學術文獻的編碼資料 | 同上 |
| 學生人數 | 8 | 特教通報網全國數據、台北市年報、衛福部統計 | 同上 |

`pick_events.py` 的挑選規則。每件都寫下「挑選理由」，顯示在介紹卡上：

- **剪報**
  - 最早和最晚的一篇。
  - 四個用詞各自第一次出現的那篇：「白痴／低能」「智能不足」「智障」「智能障礙」。
  - 分類為「政策公告及回應—立法／修法」的報導。排除外電、社會案件，以及觀點是「沈重負擔」「優生保健」的個案報導；同一部法的草案在半年內連續好幾篇時，只留第一篇。
  - 「家長拒絕標籤」「肯定障礙者」兩種觀點第一次出現的那篇。
  - 家長陳情第一次見報。
  - 2010 年代第一篇招生、安置的報導。
- **研究**
  - 第一篇研究。
  - 各種研究設計第一次出現（質性、行動、混合、文獻回顧）。
  - 第一篇權利意識研究、第一篇性教育介入研究、第一篇自我倡議研究。
  - 研究篇數最多的一年。
- **人數**
  - 各資料來源的第一年與最後一年。
  - 智能障礙學生人數的高峰（2010 年）。
  - 學習障礙、自閉症學生人數超過智能障礙的年份。
  - 全臺智能障礙者第一次超過十萬人（2014 年）。
  - 台北市特教學校智能障礙學生的減少。

### 2.2 每件事件的欄位

| 欄位 | 意思 |
|---|---|
| `id` | 例如 `l3`、`n87`、`pm1` |
| `type` | event／news／lit／people |
| `track` | 軌道：`iq` 智力測驗、`ab` 適應行為量表、`law` 法規與鑑定、`news` 剪報、`lit` 研究、`people` 學生人數 |
| `date` | `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`。只知道年就只寫年，不偽造月日 |
| `t` | 換算成小數的年份，用來決定在時間軸上的位置 |
| `precision` | 日期精確度：日／月／年／年代（例如「約 1970年代」） |
| `certainty` | sure 或 approx（約略） |
| `importance` | 重要度 1–3，決定縮放到哪個層級才寫出名稱 |
| `summary`、`memo` | 完整說明與備註 |
| `source` | 出處 |
| `why` | 挑選理由。只有從資料挑出的 32 件有 |

重要度的定法：
- 重大事件表的 18 件由人工給分：11 件是 3，7 件是 2。
- 從資料挑出的 32 件，在 `pick_events.py` 裡給 1 或 2。
- 合計：重要度 3 有 11 件、2 有 18 件、1 有 21 件。

### 2.3 易讀版

- 50 件各有一段，寫在 `source/src-zoom/10-easy.js`。
- 寫法：短句、常用詞，一句一個意思，一行一句。
- 其中 25 段沿用先前「年表」原型已寫好的易讀版，另外 25 段是這次補寫的。
- 剪報的易讀版只寫報別、日期、整理時的標題與編碼看得出來的事，**沒有讀過剪報內文**。
- 目前全部是**草稿**，卡片上標「草稿，待審閱」，尚未經特教專業人員或自我倡議者審閱。

### 2.4 背景資料

- **概覽列**：畫的是 738 篇剪報的每年篇數（`NEWS_BY_Y`）。
- **時間軸主圖**：跨度在 12 年以下時，下方多畫一條剪報刻痕，738 篇中落在這段期間的每一篇都畫一條。
- 剪報資料只到 2022 年。

## 3. 畫面構成（由上而下）

1. **頁首**（固定在畫面上方）：站名「智能障礙事件樹」、副標「可縮放時間軸」。
2. **標題與說明**：一句話說明這是什麼、怎麼縮放、點了會怎樣。
3. **工具列**
   - **軌道篩選**：六顆，可以複選，另有「全部」。每條軌道除了顏色，還有不同的形狀：
     - 智力測驗：圓
     - 適應行為量表：方
     - 法規與鑑定：菱形
     - 剪報：三角
     - 研究：六角
     - 學生人數：十字
   - **跳到年份**：輸入框加「跳到」按鈕。
   - **三個開關**：「易讀版」（預設開）、「大字」（預設關）、「減少動態」（預設跟著系統設定）。
4. **時間軸區塊**（一個圓角大框）
   - **縮放控制列**：
     - ‹ 往前
     - －
     - 縮放滑桿（左端「全覽」、右端「三年」）
     - ＋
     - 往後 ›
     - 年代選單
     - 看全部
   - **範圍文字**：例如「1985–1995 年　跨 10 年・每格 2 年・寫出全部事件」。
   - **概覽列**：全時段 1962–2025。灰色長條是每年剪報篇數，下方的彩色小刻痕是目前顯示中的事件，**黑框**是主圖目前顯示的範圍。
   - **主圖**：
     - 最上面是年份刻度與一條橫線，背景有淡淡的直向年份格線。
     - 下方是**事件卡片**，最多 5 列；卡片左緣是軌道色條，日期前有軌道形狀的小記號，下一行是事件名稱。
     - 再下方一列是**沒寫出名稱的事件**：單獨一件時畫成軌道形狀的記號，太靠近的幾件合併成圓形徽章「+N」。
     - 跨度在 12 年以下時，最下面多一條剪報刻痕，並寫出「這段期間的剪報：N 篇」。
5. **介紹卡**（時間軸下方，和時間軸同寬）
   - **沒選事件時**：虛線框加一句提示「點時間軸上的事件，這裡會出現它的介紹。」
   - **選了事件時**，卡片上緣是該軌道顏色的粗邊，由上而下是：
     1. 類型，例如「重大事件・法規與鑑定」，右上角有「關閉」按鈕
     2. 標題（襯線字）
     3. 日期（`<time datetime>`）
     4. **易讀版**：灰底區塊，最大 46em 寬
     5. 「看完整說明」收合區（`<details>`）：完整說明與備註
     6. 最下面一行小字：日期精確度、出處、挑選理由
   - 易讀版關閉時，第 4、5 項換成直接顯示完整說明。
6. **頁尾**：站名，以及「易讀版為草稿，待審閱・照片與訪談不在這一頁」。

### 3.1 顏色與字型

- 沿用正式網站的設計：淺色與深色兩套（跟著系統設定），色票寫在 `source/src/style.css` 的 CSS 變數。
- 軌道色：`--c-iq` 藍、`--c-ab` 綠、`--c-law` 土黃、`--c-news` 橘、`--c-lit` 紫紅、`--c-people` 綠。
  - 學生人數的綠和適應行為量表的綠是不同色號，但色相相近，靠形狀區分。
- 字型：思源黑體（內文）、思源宋體（標題）、霞鶩文楷（標題下的說明文字）。

## 4. 運作邏輯

### 4.1 狀態

| 狀態 | 內容 | 存在哪裡 |
|---|---|---|
| `S.e` | 選到的事件 id | 網址 `?e=` |
| `S.tracks` | 顯示中的軌道 | 網址 `?tracks=`，全部顯示時省略 |
| `Z.a`、`Z.b` | 主圖目前的時間範圍（小數年份） | 網址 `?from=&to=`，全覽時省略 |
| 易讀版、大字 | 開關 | 瀏覽器 localStorage（`idtree.zoom.easy`、`idtree.zoom.big`） |
| 減少動態 | 開關 | 瀏覽器 localStorage（`idtree.tl.calm`），沒設定時跟著系統的 `prefers-reduced-motion` |
| 滾輪提示看過了沒 | 是否已顯示 | 瀏覽器 localStorage（`idtree.zoom.hint`） |

- 網址用 `history.replaceState` 更新，不留下返回紀錄。分享網址可以回到同一件事、同一段範圍。
- 讀不到 localStorage（例如無痕模式）時，照預設值顯示。

### 4.2 縮放模型

- **時間範圍**：時間軸全長 1962.0–2026.0（64 年）。跨度最寬 64 年（全覽），最窄 3 年；`zClamp()` 確保範圍不超出兩端。
- **連續縮放**：
  - 滑桿 0–100 對應跨度 64→3 年，用**對數**對應，每推一格放大的感覺差不多。
  - ＋／－ 每次跨度減半或加倍。
  - 以「中心年份」為準：按鈕以畫面中央為中心，Ctrl＋滾輪和雙擊以滑鼠指著的那一年為中心。
- **過渡動畫**（`zTo()`）：
  - 約 320 毫秒，緩出（ease-out cubic）。
  - 跨度用**對數內插**，放大和縮小的速度感才一致；中心用線性內插。
  - 動畫的每一格只重畫兩張 SVG（主圖、概覽列）和範圍文字（`zPaint()`），結束後才整頁重畫（`render()`）並用 aria-live 唸出新範圍。
  - 新出現的卡片，透明度跟著動畫進度淡入。
  - 開啟「減少動態」時，不播動畫，直接跳到新範圍。
  - 動畫進行中如果使用者又直接改了範圍（拖曳、滑桿、滾輪、跳到年份），會先停掉動畫，免得動畫結束時把範圍蓋回去。

### 4.3 語意縮放（放大會寫出更多事件）

| 目前跨度 | 寫出名稱的事件 | 刻度間隔 | 其他 |
|---|---|---|---|
| 40 年以上 | 只有重要度 3 | 10 年 | |
| 15–40 年 | 重要度 2 以上 | 5 年 | |
| 7–15 年 | 全部 | 2 年 | 12 年以下多一條剪報刻痕 |
| 7 年以下 | 全部 | 1 年 | 同上 |

- 跨過門檻時，aria-live 會唸出「現在寫出全部事件」之類的句子。
- 年份文字之間至少隔 34px，太擠就跳過不寫。

### 4.4 卡片的排法（`zMain()`）

1. 取出目前範圍內、顯示中軌道的事件。
2. 依「重要度高→低，同重要度依時間早→晚」排序。**排法和選了哪一件無關**（見第 7 節）。
3. 重要度低於門檻的，放進「沒寫名稱」的那一列。
4. 其餘依序擺卡片：
   - **寬度** = 名稱或日期中較寬者＋留白，最寬 210px（大字時 260px）。名稱太長時截斷並加「…」，完整名稱在 aria-label 裡。
   - **水平位置**：以事件年份為中心，碰到左右邊界就往內推。
   - **列**：從第 1 列往下找第一列放得下（不和同一列的卡片重疊，間隔 6px）的位置，最多 5 列。5 列都放不下，就改放進「沒寫名稱」那一列。
5. 「沒寫名稱」那一列依時間排序。和前一件的水平距離小於 30px 的，併成同一組：
   - **一組只有一件**：畫成軌道形狀的記號（26×26 可點範圍），滑鼠移上去有提示框。
   - **一組有好幾件**：畫成「+N」徽章，提示框列出前 4 件名稱。按了會放大到剛好包住這幾件的範圍（跨度約為那幾件時間差的 2.4 倍＋1 年，不小於 3 年，不大於目前跨度的一半）。
   - **選到的事件在某個「+N」裡**：那個徽章變成深色，aria-label 寫「包含選到的『…』」。**不會把它拆出來**，以免其他東西移位。
6. **選到的事件**：卡片加粗外框，並畫一條從卡片連到時間軸橫線的直線，橫線上也畫它的軌道記號。**其他卡片沒有連線**（見第 7 節）。

### 4.5 互動一覽

| 想做的事 | 滑鼠／觸控板 | 鍵盤 | 按鈕或其他方式 |
|---|---|---|---|
| 放大、縮小 | Ctrl（Mac ⌘）＋滾輪；觸控板兩指縮放；雙擊空白處放大 | 圖裡有焦點時按 ＋／－ | ＋／－ 按鈕、滑桿 |
| 左右移動 | 拖曳主圖空白處；拖曳概覽列的框；點概覽列其他地方會把框移過去 | 圖裡有焦點時按 PageUp／PageDown（移動半個跨度） | 往前／往後（移動半個跨度）、年代選單、跳到年份 |
| 回到全覽 | | | 看全部 |
| 在事件之間移動 | | Tab 進入圖（整張圖只占一個 Tab 停點），左右鍵或上下鍵依水平位置移動，Home／End 到頭尾 | |
| 看介紹 | 點卡片或記號 | Enter 或空白鍵 | |
| 關閉介紹 | 再點一次同一件；按「關閉」 | Esc | |
| 放大一群「+N」 | 點徽章 | Enter | |
| 篩選軌道 | 點軌道按鈕 | | |

細節：
- **只滾滾輪、不按 Ctrl**：照常捲動整頁，不攔截。第一次這樣滾時，圖上浮出一次提示「按住 Ctrl（Mac 為 ⌘）再滾動滾輪即可縮放；拖曳可以左右移動」，2.6 秒後消失；瀏覽器會記住，之後不再出現。
- **用滑鼠點事件**：只換介紹卡內容，**畫面不捲動**，時間軸留在原處。
- **用鍵盤按 Enter 選事件**：焦點移到介紹卡標題，並把介紹卡捲到畫面上方。按 Esc 或「關閉」後，焦點回到時間軸上原本的事件。
- **跳到年份**：範圍變成「那一年的前 2 年到後 8 年」，選中那一年起的第一件事，焦點放在那件事上。
- **選到的事件在目前範圍外**（例如從網址直接帶入）：範圍會平移到以它為中心，跨度不變。
- **篩選掉的軌道**：在概覽列與主圖都不畫。如果選到的事件所屬軌道被關掉，選取會取消。
- **重畫時保持捲動位置**：每次重畫前先撐住時間軸區塊的高度，畫完再把捲動位置放回原處，避免畫面跳動。

### 4.6 程式結構

整頁是字串組 HTML／SVG，再用 innerHTML 放進頁面，沒有用框架或函式庫。

| 檔案 | 內容 |
|---|---|

| `source/src-zoom/20-zoom.js` | 縮放模型、`zMain()` 主圖、`zOverview()` 概覽列、動畫、滾輪、拖曳、雙擊 |

| `source/src-zoom/body.html`、`style.css` | 版面與樣式（加在正式網站的 `style.css` 之上） |
| `source/build.py` | 把以上組成單一的 `zoom.html` |

## 5. 設計依據

依據是團隊的研究報告《歷史事件時間軸與無障礙網頁設計研究報告（2026 年 10 月版）》。

| 設計 | 依據 |
|---|---|
| 概覽列＋主圖＋介紹卡 | Shneiderman「先概覽、縮放與篩選、再按需求看細節」；報告第一部分 3.2 概覽＋細節 |
| 放大會寫出更多事件 | 報告 3.3 語意縮放：縮放是換內容層級，不只是放大 |

| 概覽列畫剪報篇數 | 報告 3.2：概覽列可以用密度直方圖 |

## 6. 測試現況

- 用 axe-core 檢查 WCAG 2.0／2.1／2.2 的 A、AA 和 best-practice 規則，涵蓋：1280px 和 360px 寬、淺色和深色、大字開和關、有沒有選事件。結果是 0 個違反項目，也沒有左右捲動。
- 用 Playwright 自動測試以下操作，全部通過：
  - Ctrl＋滾輪、拖曳、雙擊、拖曳概覽列的框、滑桿、＋／－ 鍵、PageUp／PageDown。
  - 減少動態時不播動畫、網址記住範圍與事件。
  - Enter 把焦點移到介紹卡、Esc 回到原事件。
  - 點事件後所有卡片位置和捲動位置都不變，滾輪提示只出現一次。
- **還沒做的**：
  - 螢幕報讀軟體實機測試（NVDA、VoiceOver、TalkBack）。
  - 實體手機與 Safari、Firefox 測試，以及真的觸控板。
  - 請身心障礙者（特別是智能障礙者）試用。
  - 易讀版的審閱。

## 7. 使用者已經明確要求的事（改進時請保留）

依使用者回饋的先後列出：

1. **縮放要「感覺得到」**：原本只有四個固定層級、瞬間切換，使用者覺得沒有在放大。現在改成連續縮放加過渡動畫，並支援 Ctrl＋滾輪、觸控板、拖曳、雙擊。
2. **獨立的一頁**：不連到正式網站或比較頁。
3. **時間軸占滿主畫面，介紹卡放在時間軸下方**，不要放在右側欄。
4. **介紹卡只留這件事本身的介紹**：已拿掉「往前看／往後看」（因果關聯）、「上一件／下一件」、「同一年的政策類剪報」，以及照片、剪報、訪談節選。
5. **加入易讀版**，放在介紹卡最上面。
6. **操作提示不要一直跳出**：只在第一次出現。
7. **拿掉卡片和時間軸之間的連線**，使用者覺得太亂。現在只有選到的那件有線。
8. **點了事件，卡片不要移動、畫面不要捲動**：原本選到的卡片會跳到第一列、其他卡片重排，畫面也會捲去顯示介紹卡，使用者覺得很亂。

## 8. 已知的限制與待解的問題（歡迎針對這些提出改進）

1. **點了事件後看不到介紹卡**：用滑鼠點時畫面不捲動（使用者的要求），但介紹卡在時間軸下方，螢幕不夠高時可能完全在畫面外，使用者不知道已經出現介紹。要怎麼在不移動時間軸的前提下讓人注意到？
2. **剪報事件的名稱看不懂**：剪報的標題取自整理時的檔名（例如「幼獅社」「歧視」「設班 教育局告家長書」），單看名稱不知道在講什麼。
3. **卡片名稱會被截斷**：名稱太長時卡片最寬 210px，會截成「…」，看不到全名。
4. **全覽時事件擠在一起**：1980–1990 年代事件密集，全覽時大部分是「+N」，只看得到 11 件重要事件的名稱。
5. **「+N」徽章只說數量**：看不出裡面是哪幾類事件，滑鼠移上去才有提示框，手機和鍵盤使用者看不到這個提示框。
6. **同色系的軌道不易分辨**：學生人數的綠和適應行為量表的綠，只靠形狀區分；記號在全覽時很小。
7. **手機上的操作**：
   - 手機上沒有兩指縮放主圖（只有按鈕和滑桿）。
   - 在主圖上用手指左右拖曳，可能被瀏覽器當成捲動頁面而沒有平移（尚未在實機確認）。
   - 窄螢幕上時間軸只有約 330px 寬，能寫出名稱的卡片很少。
8. **概覽列只畫剪報篇數**：不是 50 件事件的密度，兩者容易混淆。概覽列也沒有鍵盤操作（但有其他按鈕可以做到同樣的事）。
9. **縮放門檻是固定數字**（40 年、15 年、12 年），不是依畫面寬度或實際擠不擠決定；寬螢幕上可能還放得下更多名稱卻沒有寫出來。
10. **每次縮放結束都整頁重畫**：用 innerHTML 重建工具列、時間軸和介紹卡。目前資料量小沒有效能問題，但寫法比較粗糙。
11. **易讀版是草稿**：剪報的易讀版是從標題推出來的，需要對照原剪報與專家審閱。
12. **時間軸只有事件**：沒有正式網站的「報紙用詞比例」背景色帶。是否要加回來、怎麼加才不亂，還沒有決定。
13. **沒有文字清單**：時間軸以外，沒有等價的純文字年表（比較頁的版本 1、2 有）。研究報告建議每條互動時間軸都要有等價的文字或表格版本。
